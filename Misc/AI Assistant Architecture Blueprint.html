The "Hinglish" Challenge

Code-switching between Hindi and English requires specific model characteristics. Standard Llama-3 models handle romanized Hindi passably but often default back to English. Models fine-tuned on multilingual corpora (like Cohere Command R+ or Gemini) show superior adherence to native Hinglish sentence structures without requiring massive few-shot prompting.

Why LiteLLM over OpenRouter?

For HAKI, hosting LiteLLM locally on the Mac ensures 0ms network overhead for routing logic. It allows you to utilize your own free-tier API keys directly (Groq, Cerebras, Google) rather than paying OpenRouter's markup or relying on their rotating free models which change unpredictably.

Bifrost / Custom Rust Gateways

While Rust-based gateways offer microsecond latency, LiteLLM's Python proxy overhead (~5ms) is negligible compared to network transit times. The developer velocity of LiteLLM's standard OpenAI-compatible endpoints wins out.

Definitive HAKI Architecture

Based on current free tiers, latency requirements, and the need for native Hinglish support, implement the following stack using LiteLLM as the local traffic cop.

1. The Engine Room

  • Gateway Router: LiteLLM (Local via Python) Intercepts all HAKI requests. Handles automatic retries and fallback cascading based on API HTTP 429 status codes.
  • Fast Conversational Core: Cerebras (Llama-3 8B) Fallback 1: Groq | Fallback 2: Together AI
    Provides the sub-20ms TTFT required. System prompts must be tuned to force natural Hinglish, as base Llama-3 leans heavily English.
  • Heavy Context/Vision: Gemini 1.5 Flash Handles Obsidian vault RAG and screen interpretation using Google's massive 1M token free tier.

2. The Sensory Layer

  • STT Stream: Deepgram Nova-2 Open a WebSocket connection from the Mac. Deepgram handles raw streaming audio and returns transcripts in ~250ms with excellent Hinglish detection.
  • TTS Stream: Cartesia Sonic Feed Cerebras tokens chunks directly into Cartesia's WebSockets API. At ~135ms latency, audio generation begins before the LLM finishes the sentence.
  • Estimated TTFA (Time-To-First-Audio): ~380ms (Deepgram 200ms + Network/LiteLLM 20ms + Cerebras TTFT 20ms + Cartesia 140ms). While slightly over the strict 300ms budget, chunking optimizations and parallelizing STT finalizing with LLM predicting can bring it to ~300ms.

Pro Tip for Budget: Utilize Anthropic's new developer console free credits as a tertiary fallback in OpenRouter for complex reasoning tasks that Llama-3 8B fails at.
